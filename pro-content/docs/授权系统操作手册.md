## 1. 系统原理

### 1.1 为什么要用非对称加密？

**问题**：开源仓库的代码所有人可见。如果用对称加密（HMAC），签名密钥和验证密钥是同一个，放在开源仓库里等于告诉所有人"这是密钥，你们自己签名吧"。

**解决**：用 Ed25519 非对称加密，两个密钥不同：

```
私钥（Private Key）→ 签名 → 生成激活码     → 只在你手里（闭源仓库）
公钥（Public Key） → 验证 → 校验激活码     → 放在开源仓库，人人可见
```

**关键**：公钥只能验证，不能签名。就像锁和钥匙的关系：
- 公钥 = 锁（所有人都能用锁检查东西是否被打开过）
- 私钥 = 钥匙（只有你能开锁/签名）

### 1.2 Ed25519 签名流程

```
生成激活码（你操作）：
  消息 = "personal:2027-12-31"
  签名 = Ed25519_签名(私钥, 消息)  →  一长串 hex
  激活码 = "personal:2027-12-31:签名hex"

验证激活码（用户应用操作）：
  拆分激活码 → type="personal", expires="2027-12-31", sig=签名hex
  结果 = Ed25519_验证(公钥, 消息, 签名)  →  True/False
```

### 1.3 激活码格式

```
personal:2027-12-31:a7c5b1fb281c1f19439619d70f9916c7...
   │         │              │
   │         │              └── Ed25519 签名（128 字符 hex）
   │         └── 过期日期（或 lifetime）
   └── 版本类型（personal / professional）
```

### 1.4 安全边界

| 谁能做什么 | 说明 |
|-----------|------|
| 你（开发者）| 用私钥生成任意激活码 |
| 开源用户 | 用公钥验证激活码，但**无法**生成 |
| 攻击者 | 能看到公钥，但**无法**从公钥反推私钥 |
| 付费用户 | 修改代码绕过验证是可能的，但失去后续更新支持 |

## 2. 密钥管理

### 2.1 密钥文件位置

```
闭源仓库 (D:/04.量化/quantsync-pro/)
├── license_private_key.pem    ← 私钥，最重要的文件！
├── gen_license.py             ← 生成脚本
├── generated_codes.txt        ← 已生成记录
└── LICENSE_SYSTEM.md          ← 技术文档

开源仓库 (D:/04.量化/quantsync-etl/)
└── backend/app/core/license_manager.py
    └── _PUBLIC_KEY_PEM = b"..."   ← 公钥硬编码在此
```

### 2.2 私钥备份

**私钥丢了 = 再也无法生成新激活码**，已有的激活码不受影响（公钥验证仍然有效）。

备份方式（选一种）：
- 把 `license_private_key.pem` 复制到 U 盘 / 云盘加密存储
- 记录到密码管理器（1Password / Bitwarden）
- 打印出来锁保险箱（夸张但有效）

### 2.3 密钥泄露怎么办？

如果私钥泄露（比如不小心提交到开源仓库了）：

1. **重新生成密钥对**：
   ```bash
   cd D:/04.量化/quantsync-pro
   python -c "
   from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PrivateKey
   from cryptography.hazmat.primitives import serialization

   private_key = Ed25519PrivateKey.generate()
   public_key = private_key.public_key()

   private_pem = private_key.private_bytes(
       encoding=serialization.Encoding.PEM,
       format=serialization.PrivateFormat.PKCS8,
       encryption_algorithm=serialization.NoEncryption())
   public_pem = public_key.public_bytes(
       encoding=serialization.Encoding.PEM,
       format=serialization.PublicFormat.SubjectPublicKeyInfo)

   open('license_private_key.pem', 'wb').write(private_pem)
   print('新公钥:')
   print(public_pem.decode())
   "
   ```

2. **更新开源仓库的公钥**：把新公钥替换到 `license_manager.py` 的 `_PUBLIC_KEY_PEM`

3. **重新给所有付费用户发新激活码**（用新私钥生成）

4. 旧激活码全部失效

## 3. 生成激活码

### 3.1 基本命令

```bash
# 进入闭源仓库
cd D:/04.量化/quantsync-pro

# 生成个人版永久激活码
python gen_license.py personal

# 生成专业版永久激活码
python gen_license.py professional
```

### 3.2 带过期时间

```bash
# 个人版，到期 2027-12-31
python gen_license.py personal --expires 2027-12-31

# 专业版，到期 2027-06-30
python gen_license.py professional --expires 2027-06-30
```

### 3.3 带标签（区分渠道）

```bash
# 知识星球会员共享码
python gen_license.py personal --expires 2027-12-31 --label zsxq-2027

# 闲鱼用户独立码
python gen_license.py professional --label xianyu-user001

# 朋友圈推广码
python gen_license.py personal --expires 2027-03-31 --label wechat-spring
```

标签不影响激活码功能，只是方便你记录这个码是从哪个渠道发出的。

### 3.4 批量生成

```bash
# 一次生成 10 个个人版码
python gen_license.py personal --count 10 --expires 2027-12-31

# 一次生成 5 个专业版码
python gen_license.py professional --count 5
```

### 3.5 输出示例

```
=== 金智汇联 ETL 激活码生成器 ===
类型: personal
过期: 2027-12-31
标签: zsxq-2027
数量: 1

  1. personal:2027-12-31:a7c5b1fb281c1f19439619d70f9916c7...

共生成 1 个激活码
已追加到: D:\04.量化\quantsync-pro\generated_codes.txt
```

### 3.6 完整参数速查

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `type` | 是 | - | `personal` 或 `professional` |
| `--expires` | 否 | `lifetime` | 日期 `YYYY-MM-DD` 或 `lifetime` |
| `--label` | 否 | 空 | 渠道标签，方便记录 |
| `--count` | 否 | `1` | 批量生成数量 |

## 4. 分发激活码

### 4.1 知识星球会员（共享码）

```bash
# 生成一个所有会员共享的年度码
python gen_license.py personal --expires 2027-12-31 --label zsxq-2027

# 把生成的激活码发到知识星球置顶帖
```

**特点**：
- 一个码所有会员共用
- 到期后统一失效，需要续期
- 每年生成一次新码

### 4.2 闲鱼用户（独立码）

```bash
# 每个用户生成独立码
python gen_license.py professional --label xianyu-user001

# 通过闲鱼聊天发给对应用户
```

**特点**：
- 一用户一码
- 通常永久有效
- 如果用户换机器，可以补发新码（旧码作废）

### 4.3 分发时的话术模板

```
你好！感谢购买金智汇联 ETL 专业版。

激活码：personal:2027-12-31:a7c5b1fb...

使用方式：
1. 打开应用 → 点击「License 管理」
2. 在「激活码」输入框粘贴上面的激活码
3. 点击「激活」按钮
4. 然后在「导入专业版内容包」区域上传 .jspack 文件
```

## 5. 用户激活流程

### 5.1 用户视角

```
1. 安装开源版
   git clone https://github.com/ScottZt/jinzhi-huilian-etl.git
   python backend/run_server.py

2. 看到免费版功能有限
   点击「升级付费版」→ 查看购买指南

3. 购买（知识星球/闲鱼）
   获得：激活码 + .jspack 内容包文件

4. 激活 License
   License 管理 → 输入激活码 → 点击「激活」
   → 显示"个人版"或"专业版"

5. 导入内容包
   License 管理 → 导入专业版内容包 → 上传 .jspack
   → 25 个工作流 + 6 个插件导入成功

6. 使用专业版功能
   导入示例 → 勾选专业版工作流 → 导入使用
```

### 5.2 技术验证流程

当用户输入激活码时，应用内部发生的事：

```python
# 1. 用户输入: personal:2027-12-31:a7c5b1fb...
# 2. 拆分为: type="personal", expires="2027-12-31", sig="a7c5b1fb..."
# 3. 调用 _verify_activation(type, expires, sig)
# 4. 使用硬编码的公钥验证 Ed25519 签名
# 5. 验证通过 → 检查过期时间 → 保存 License 到 SQLite
# 6. 后续所有功能检查都基于这个 License 类型
```

### 5.3 License 存储位置

激活后 License 信息保存在 SQLite 数据库的 metadata 表中：

```
数据库: backend/data/quantsync.db
表: metadata
键: _license_meta
值: {"type": "personal", "machine_code": "XXX", "expires_at": "2027-12-31T00:00:00", ...}
```

## 7. 常见问题

### Q1: 激活码过期了怎么办？

用户打开应用时会看到 License 降级为 free。重新发一个码激活即可。

```bash
# 给老用户续期
python gen_license.py personal --expires 2028-12-31 --label renew-user001
```

### Q2: 用户换电脑了怎么办？

License 绑定了机器码。换电脑需要重新激活：

```bash
# 生成新码发给用户
python gen_license.py professional --label xianyu-user001-renew
```

旧码在新机器上无效（因为机器码不同）。

### Q3: 如何查看用户激活了没有？

用户应用里：`License 管理` 弹框会显示当前版本、机器码、过期时间。

### Q4: 开发者模式是什么？

设置环境变量 `JZHL_DEV_MODE=true` 可以跳过所有 License 检查。用于开发测试：

```bash
JZHL_DEV_MODE=true python backend/run_server.py
```

### Q5: 忘了上次给某用户发了什么码？

查看 `generated_codes.txt`：

```bash
cat D:/04.量化/quantsync-pro/generated_codes.txt
# 或搜索特定标签
grep "xianyu-user001" D:/04.量化/quantsync-pro/generated_codes.txt
```

### Q6: 能不能让一个码在多台机器上用？

当前设计是一码一机。如果要支持多机器，需要：
1. 去掉机器码绑定逻辑
2. 或者增加「解绑」功能让用户自助迁移

### Q7: 万一有人破解了代码绕过验证？

可能的，但：
1. 他拿不到后续更新
2. 他拿不到内容包（工作流 JSON 不在开源仓库）
3. 开源项目靠口碑和服务留住用户，而非强制验证

## 8. 安全检查清单

每次发布前检查：

- [ ] `license_private_key.pem` 没有在开源仓库中
- [ ] `gen_license.py` 没有在开源仓库中
- [ ] `_SECRET_KEY_PARTS` 或任何密钥字符串不在开源代码中
- [ ] `generate_activation_code()` 函数不在开源代码中
- [ ] 开源仓库的 `_PUBLIC_KEY_PEM` 和闭源仓库的私钥是配对的
- [ ] `generated_codes.txt` 没有在开源仓库中

一键检查命令：

```bash
cd D:/04.量化/quantsync-etl

echo "=== 检查开源仓库是否泄露敏感信息 ==="

# 检查私钥文件
if [ -f "license_private_key.pem" ]; then
    echo "[FAIL] 私钥文件在开源仓库！"
else
    echo "[PASS] 私钥文件不在开源仓库"
fi

# 检查生成函数
if grep -r "generate_activation_code" backend/app/; then
    echo "[FAIL] 发现 generate_activation_code！"
else
    echo "[PASS] 没有 generate_activation_code"
fi

# 检查签名密钥
if grep -r "_SECRET_KEY_PARTS\|_sign_activation" backend/app/; then
    echo "[FAIL] 发现签名相关代码！"
else
    echo "[PASS] 没有签名相关代码"
fi

# 检查公钥存在
if grep -r "_PUBLIC_KEY_PEM" backend/app/; then
    echo "[PASS] 公钥存在"
else
    echo "[FAIL] 公钥缺失！"
fi
```
