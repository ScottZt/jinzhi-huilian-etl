# 仓库发布操作手册

> 本手册说明如何向开源仓库（GitHub）和私有仓库（Gitee）发布代码。
> 配套文档：`授权系统操作手册.md`

---

## 核心架构：分支隔离

```
本地工作目录 (quantsync-etl)
    │
    ├── main 分支（完整内容，含 pro-content/）
    │   └── git push 金汇智连 main  →  Gitee 私有仓库
    │
    └── open-source 分支（脱敏内容，无 pro-content/）
        └── git push origin open-source:main  →  GitHub 公开仓库
```

### 两个分支的区别

| 内容 | main（Gitee 私有） | open-source（GitHub 公开） |
|------|:---:|:---:|
| 核心引擎代码 | ✅ | ✅ |
| 前端 UI 代码 | ✅ | ✅ |
| 内容包导入机制 | ✅ | ✅ |
| 购买指南弹框 | ✅ | ✅ |
| License 验证 + 公钥 | ✅ | ✅ |
| **pro-content/ 目录** | ✅ | ❌ |
| **工作流 JSON** | ✅ | ❌ |
| **高级官方插件** | ✅ | ❌ |
| **License 私钥** | ✅ | ❌ |
| **激活码生成脚本** | ✅ | ❌ |

## 日常开发流程

### 在哪个分支开发？

**在 `main` 分支开发。**

```bash
cd D:/04.量化/quantsync-etl

# 确保在 main 分支
git checkout main
```

### 开发完成后提交

```bash
# 1. 查看变更
git status
git diff

# 2. 安全检查（见下方"安全检查"章节）

# 3. 提交到 main
git add -A
git commit -m "feat: 描述改动"

# 4. 同步到 open-source 分支
git checkout open-source
git merge main --no-edit

# 5. 在 open-source 上删除敏感内容
#    （如果新增的文件涉及敏感内容）
# rm -rf pro-content/ 的新增部分
# rm backend/plugins/official_*.py（如果有新增）

# 6. 提交 open-source 的清理
git add -A
git commit -m "chore: 同步 main 并清理敏感内容" --allow-empty

# 7. 推送
git push 金汇智连 main          # main → Gitee
git checkout main               # 切回 main
git push origin open-source:main # open-source → GitHub
```

### 简化版（无敏感内容变更时）

如果本次改动**没有新增敏感内容**，可以简化：

```bash
cd D:/04.量化/quantsync-etl
git checkout main

# 开发...

git add -A && git commit -m "feat: xxx"

# 同步两个分支
git checkout open-source && git merge main --no-edit
git checkout main

# 推送
git push 金汇智连 main
git push origin open-source:main
```

## 发布新版本

```bash
cd D:/04.量化/quantsync-etl
git checkout main

# 确保两个分支都已提交
git status  # main 应该是 clean
git checkout open-source && git status  # open-source 也应该是 clean
git checkout main

# 打 Tag
git tag -a v1.2.0 -m "feat: 新版本描述"

# Tag 需要在两个分支上都打
git checkout open-source
git tag -a v1.2.0 -m "feat: 新版本描述"
git checkout main

# 推送 Tag
git push 金汇智连 main
git push 金汇智连 v1.2.0
git push origin open-source:main
git push origin v1.2.0
```

## 安全检查（每次提交前必做！）

在 `open-source` 分支上运行：

```bash
cd D:/04.量化/quantsync-etl
git checkout open-source

echo "=== 安全检查 ==="

# 1. pro-content 不应该存在
echo -n "1. pro-content/: "
ls pro-content/ 2>/dev/null && echo "   [FAIL] 存在！" || echo "[PASS] 不存在"

# 2. 无私钥
echo -n "2. 私钥文件: "
find . -name "license_private_key.pem" -not -path "./.git/*" 2>/dev/null | grep -q . && echo "[FAIL] 发现！" || echo "[PASS] 无"

# 3. 无生成函数
echo -n "3. 生成函数: "
grep -r "def generate_activation_code" backend/app/ 2>/dev/null && echo "[FAIL] 发现！" || echo "[PASS] 无"

# 4. 无官方插件
echo -n "4. 官方插件: "
OFFICIAL_COUNT=$(find backend/plugins/ -name "official_*.py" 2>/dev/null | wc -l)
[ "$OFFICIAL_COUNT" -gt 0 ] && echo "[FAIL] 发现 $OFFICIAL_COUNT 个！" || echo "[PASS] 无"

# 5. 无工作流 JSON 泄露
echo -n "5. 工作流 JSON: "
python -c "
import re,json
with open('backend/app/static/example_workflows.js','r',encoding='utf-8') as f: c=f.read()
m=re.search(r'window\.EXAMPLE_WORKFLOWS_DATA = (\{.+?\});',c,re.S)
if m:
    d=json.loads(m.group(1))
    leaked=[e['id'] for e in d['examples'] if 'workflow' in e and e['workflow']]
    print(f'[FAIL] 泄露 {len(leaked)} 个' if leaked else '[PASS] 无泄露')
else:
    print('[WARN] 未找到文件')
"

echo "=== 检查完成 ==="
git checkout main
```

## 分支同步脚本

创建一个辅助脚本，简化日常同步操作：

```bash
# 保存为 scripts/sync-branches.sh
#!/bin/bash
set -e
cd "$(dirname "$0")/.."

echo "=== 同步分支 ==="

# 确保在 main 且干净
git checkout main
if [ -n "$(git status --porcelain)" ]; then
    echo "[error] main 分支有未提交的更改"
    exit 1
fi

# 同步到 open-source
git checkout open-source
git merge main --no-edit

echo "[ok] open-source 已同步到 main 最新状态"

# 安全检查
echo ""
echo "=== 安全检查 ==="
if [ -d "pro-content" ]; then
    echo "[WARN] pro-content/ 存在于 open-source 分支"
    echo "       请手动删除并 commit"
else
    echo "[PASS] pro-content/ 不存在"
fi

git checkout main
echo ""
echo "[ok] 已切回 main 分支"
```
