# 因子库操作手册

> 本文档介绍金智汇连 ETL 的基础因子库功能，包括因子计算节点、因子写入节点、因子查询 API 的使用方法。

---

## 一、功能概述

基础因子库是 ETL 的**数据基座**功能之一，用于标准化生产、存储、查询量化因子数据。

**核心能力**：
- 📊 **9 种内置因子计算**：MA/EMA/MACD/RSI/BOLL/收益率/波动率/ATR/BIAS
- 💾 **DuckDB 宽表存储**：每个因子一张表，高性能查询
- 🔌 **标准化 API**：支持单因子/多因子/统计信息查询
- 🔄 **增量更新**：支持 upsert 模式，高效增量生产

---

## 二、工作流节点

### 2.1 因子计算节点（factor_compute）

**节点类型**：`factor_compute`  
**分类**：因子库  
**功能**：根据输入数据计算指定类型的因子

#### 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `factor_id` | text | ma_5 | 因子 ID，用于标识因子 |
| `compute_type` | select | ma | 计算类型（见下表） |
| `params_json` | text | {"window": 5} | 计算参数 JSON |
| `source_column` | text | close | 源数据字段名 |
| `code_column` | text | code | 股票代码字段名 |
| `date_column` | text | dt | 日期字段名 |

#### 支持的计算类型

| 类型 | 名称 | 参数示例 | 输出列 |
|------|------|---------|--------|
| `ma` | 移动平均 | `{"window": 5}` | `factor_value` |
| `ema` | 指数移动平均 | `{"span": 10}` | `factor_value` |
| `macd` | MACD 指标 | `{"fast": 12, "slow": 26, "signal": 9}` | `factor_value`（MACD柱）, `_factor_dif`, `_factor_dea` |
| `rsi` | RSI 相对强弱 | `{"window": 14}` | `factor_value` |
| `boll` | 布林带 | `{"window": 20, "std_mult": 2}` | `factor_value`（中轨）, `_factor_boll_mid/upper/lower` |
| `return` | 收益率 | `{"window": 1}` | `factor_value` |
| `volatility` | 年化波动率 | `{"window": 20}` | `factor_value` |
| `atr` | ATR 真实波幅 | `{"window": 14}` | `factor_value` |
| `bias` | BIAS 乖离率 | `{"window": 6}` | `factor_value` |

#### 输出格式

节点输出统一为三列：

| 列名 | 类型 | 说明 |
|------|------|------|
| `code` | string | 股票代码 |
| `dt` | string | 日期 |
| `factor_value` | float | 因子值 |

> 对于 MACD/BOLL 等多值因子，还会输出 `_factor_*` 辅助列。

#### 使用示例

```json
{
  "id": "n1",
  "type": "factor_compute",
  "parameters": {
    "factor_id": "ma_5",
    "compute_type": "ma",
    "params_json": "{\"window\": 5}",
    "source_column": "close",
    "code_column": "code",
    "date_column": "dt"
  }
}
```

### 2.2 因子写入节点（factor_write）

**节点类型**：`factor_write`  
**分类**：因子库  
**功能**：将因子数据写入 DuckDB 因子库

#### 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `factor_id` | text | （必填） | 因子 ID，如 `ma_5` |
| `db_path` | text | D:/data/factor_data.duckdb | DuckDB 文件路径 |
| `write_mode` | select | upsert | 写入模式：`upsert`/`append`/`replace` |
| `code_column` | text | code | 代码字段名 |
| `date_column` | text | dt | 日期字段名 |
| `value_column` | text | factor_value | 值字段名 |
| `register_meta` | checkbox | true | 是否注册因子元数据 |
| `factor_name` | text | （可选） | 因子名称（用于元数据） |
| `compute_type` | select | other | 计算类型（元数据） |
| `params_json_meta` | text | {} | 参数 JSON（元数据） |

#### 写入模式

| 模式 | 说明 |
|------|------|
| `upsert` | 存在则更新，不存在则插入（默认） |
| `append` | 仅追加，存在则跳过 |
| `replace` | 清空后重写 |

#### 存储结构

**因子数据表**（每个因子一张表）：

```sql
CREATE TABLE factor_{factor_id} (
    code VARCHAR,
    dt VARCHAR,
    factor_value DOUBLE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (code, dt)
);
```

**因子注册表**：

```sql
CREATE TABLE factor_registry (
    factor_id VARCHAR PRIMARY KEY,
    factor_name VARCHAR,
    factor_type VARCHAR,      -- L0/L1/L2/L3
    compute_type VARCHAR,
    params_json VARCHAR,
    source_column VARCHAR,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);
```

### 5.2 DuckDB 直连消费（推荐）

```python
import duckdb

# 直连因子库（性能更好）
conn = duckdb.connect("D:/data/factor_data.duckdb", read_only=True)

# 单因子查询
df = conn.execute("""
    SELECT * FROM factor_ma_5
    WHERE code = '000001' AND dt >= '2024-01-01'
    ORDER BY dt
""").fetchdf()

# 多因子 JOIN
df_wide = conn.execute("""
    SELECT t0.code, t0.dt,
           t0.factor_value as ma_5,
           t1.factor_value as ma_20,
           t2.factor_value as rsi_14
    FROM factor_ma_5 t0
    JOIN factor_ma_20 t1 ON t0.code = t1.code AND t0.dt = t1.dt
    JOIN factor_rsi_14 t2 ON t0.code = t2.code AND t0.dt = t2.dt
    WHERE t0.code IN ('000001', '600000')
    ORDER BY t0.code, t0.dt
""").fetchdf()

conn.close()
```

## 七、增量更新策略

### 7.1 为什么需要增量更新？

全量重新计算因子的问题：
- ⏱️ **耗时**：MA20 需要回溯 20 天数据，全量计算耗时随数据量线性增长
- 💾 **浪费**：已有数据被重复计算和覆盖
- 🔒 **风险**：全量覆盖期间，下游消费可能读到不完整数据

### 7.2 增量更新原理

```
┌────────────────────────────────────────────────────────────┐
│  因子库现有数据                                              │
│  factor_ma_5: code=000001, dt=2024-01-01 ~ 2024-12-20     │
│  最新日期: 2024-12-20                                       │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────┐
│  Step 1: 查询因子库最新日期                                  │
│  SELECT MAX(dt) FROM factor_ma_5 WHERE code = '000001'    │
│  → 2024-12-20                                              │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────┐
│  Step 2: 拉取源数据（带回看窗口）                             │
│  开始日期 = MAX(dt) - lookback + 1                          │
│  = 2024-12-20 - 5 + 1 = 2024-12-16                         │
│  拉取 2024-12-16 ~ 2024-12-31 的数据                        │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────┐
│  Step 3: 计算因子（包含回看数据）                             │
│  MA5(2024-12-16) 需要 2024-12-12 ~ 2024-12-16 的数据       │
│  确保边界值正确计算                                          │
└────────────────────────────────────────────────────────────┘
                          │
                          ▼
┌────────────────────────────────────────────────────────────┐
│  Step 4: 过滤出新增日期，写入因子库                           │
│  只写入 dt > 2024-12-20 的数据                              │
│  write_mode: upsert（防止重复）                              │
└────────────────────────────────────────────────────────────┘
```

### 7.3 不同因子类型的回看窗口

| 因子类型 | 参数 | 回看窗口 | 说明 |
|---------|------|---------|------|
| `ma` | window=5 | 4 天 | 需要前 4 天数据计算当天 MA5 |
| `ema` | span=10 | 9 天 | EMA 需要前 span-1 天 |
| `macd` | fast=12, slow=26 | 25 天 | 需要前 slow-1 天 |
| `rsi` | window=14 | 14 天 | 需要前 window 天 |
| `boll` | window=20 | 19 天 | 需要前 window-1 天 |
| `return` | window=5 | 5 天 | 需要前 window 天 |
| `volatility` | window=20 | 20 天 | 需要前 window 天 |
| `atr` | window=14 | 14 天 | 需要前 window 天 |
| `bias` | window=6 | 6 天 | 需要前 window 天 |

> **建议**：回看窗口 = 最大参数值 + 5 天缓冲，确保边界计算正确。

### 7.4 增量更新工作流设计

#### 方案一：固定回看天数（简单）

适用于每日定时任务，数据量不大的场景。

```json
{
  "nodes": [
    {
      "id": "n1",
      "type": "source_fetch",
      "parameters": {
        "source_type": "tdx",
        "codes": "000001,600000",
        "interval": "D",
        "time_mode": "lookback",
        "lookback_days": 30
      }
    },
    {
      "id": "n2",
      "type": "factor_compute",
      "parameters": {
        "factor_id": "ma_20",
        "compute_type": "ma",
        "params_json": "{\"window\": 20}",
        "source_column": "close"
      }
    },
    {
      "id": "n3",
      "type": "factor_write",
      "parameters": {
        "factor_id": "ma_20",
        "db_path": "D:/data/factor_data.duckdb",
        "write_mode": "upsert"
      }
    }
  ]
}
```

**特点**：
- 每次拉取最近 30 天数据
- `upsert` 模式自动处理重复键
- 简单可靠，适合中小规模数据

#### 方案二：动态增量（高效）

适用于大规模数据，需要精确控制增量范围的场景。

```python
# 自定义 Python 脚本实现动态增量
import duckdb
from datetime import datetime, timedelta

def get_latest_factor_date(factor_id, code, db_path):
    """查询因子库最新日期"""
    conn = duckdb.connect(db_path, read_only=True)
    try:
        result = conn.execute(f"""
            SELECT MAX(dt) FROM factor_{factor_id}
            WHERE code = '{code}'
        """).fetchone()
        return result[0] if result[0] else None
    finally:
        conn.close()

def process(df, params):
    """增量处理逻辑"""
    # 这里可以实现更复杂的增量逻辑
    return df
```

#### 方案三：分区增量（超大规模）

适用于多股票、多因子的大规模生产场景。

```
┌──────────────────────────────────────────────────────────┐
│  Pipeline: 因子增量生产                                     │
│                                                           │
│  ┌────────────┐                                          │
│  │ 查询最新日期 │ → 按股票分组                              │
│  └─────┬──────┘                                          │
│        │                                                  │
│        ▼                                                  │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐         │
│  │ 股票 A 增量 │  │ 股票 B 增量 │  │ 股票 C 增量 │  ...     │
│  └─────┬──────┘  └─────┬──────┘  └─────┬──────┘         │
│        │               │               │                  │
│        └───────────────┼───────────────┘                  │
│                        ▼                                  │
│               ┌────────────┐                              │
│               │ 合并写入    │                              │
│               └────────────┘                              │
└──────────────────────────────────────────────────────────┘
```

### 7.5 写入模式对比

| 模式 | SQL 行为 | 适用场景 | 性能 |
|------|---------|---------|------|
| `upsert` | `INSERT OR REPLACE` | 增量更新（默认） | ⭐⭐⭐⭐ |
| `append` | `INSERT` | 确保无重复的新数据 | ⭐⭐⭐⭐⭐ |
| `replace` | `DELETE` + `INSERT` | 全量重算 | ⭐⭐ |

### 7.6 增量更新注意事项

1. **回看窗口必须足够**：确保边界值计算正确，避免产生 NaN
2. **使用 upsert 模式**：防止重复写入，保证数据一致性
3. **检查数据完整性**：增量更新后，验证最新日期是否正确
4. **异常处理**：如果源数据缺失，增量更新可能产生错误，需要监控

### 7.7 增量更新监控

通过 API 检查因子库状态：

```bash

curl "http://localhost:8000/api/factors/stats"

# 检查特定因子的最新日期
```

## 八、常见问题

### Q1: 因子 ID 命名规范？

建议使用 `{类型}_{参数}` 格式，如：
- `ma_5`, `ma_20`
- `rsi_14`
- `macd`
- `ret_1d`, `ret_5d`
- `volatility_20`

### Q2: 如何增量更新因子？

使用 `write_mode: upsert`，每次运行工作流时只计算新增数据，DuckDB 会自动处理重复键。

### Q3: 多股票批量计算时如何分组？

`factor_compute` 节点会自动按 `code_column` 分组计算，确保不同股票的因子值独立计算。

### Q4: 如何查看已生产的因子？

调用 `GET /api/factors/registry` 或 `GET /api/factors/stats`。

### Q5: 因子数据如何备份？

因子库存储在 DuckDB 文件中（默认 `D:/data/factor_data.duckdb`），直接备份该文件即可。

打开浏览器访问：`http://localhost:8000/static/factor-library.html`

### 9.2 功能说明

| 功能 | 说明 |
|------|------|
| 📊 查看因子列表 | 按因子类型筛选，显示所有已注册因子 |
| 📈 查看因子详情 | 点击因子查看详情、统计信息、数据预览 |
| 🗑️ 删除因子 | 删除因子数据表和注册信息（不可恢复） |
| 🔄 刷新数据 | 重新加载因子库状态 |
