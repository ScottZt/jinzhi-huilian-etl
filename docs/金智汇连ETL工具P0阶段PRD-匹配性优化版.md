# 金智汇连 ETL 工具 P0 阶段 PRD（匹配性优化改造版）

## 1. 文档目标
- 将《金智汇连ETL豆包版PRD》的阶段目标与《金智汇连ETL工具P0阶段PRD》的用户故事进行逐项对齐。
- 在不破坏第一阶段 0-3 个月交付节奏的前提下，补齐“金融量化场景专业性 + 可用性 + 合规安全”关键缺口。
- 输出可直接用于研发排期、测试验收、上线评审的 P0 改造清单。

## 2. 结论摘要（先看这个）
- 现有 P0 文档已覆盖基础闭环主干：`数据接入 -> 可视化处理 -> 数据落地 -> AI脚本生成`。
- 主要缺口集中在 4 个方面：`合规可执行机制`、`量化数据质量保障`、`流程调试效率`、`任务可靠性`。
- 建议采用“`P0 必做` + `P0.5 可并行` + `P1 延后`”三级落地，确保 0-3 个月内形成可上线且有差异化的最小可用产品（MVP+）。

## 3. 匹配性评估矩阵（两份 PRD 对齐）
| 维度 | 豆包版 PRD 期望 | 现有 P0 用户故事覆盖度 | 匹配结论 | 改造建议 |
|---|---|---|---|---|
| 数据源接入 | 合规数据源 + 自定义 API + 合规提示 | 已覆盖 Tushare/CTP/自定义 API/本地文件/合规弹窗 | 高匹配 | 增加“合规模式”开关与不可绕过审计日志 |
| 数据质量 | 缺失补全、异常处理、复权、停牌涨跌停 | 已覆盖缺失值、异常值、复权、标记 | 中高匹配 | 增加“数据完整性校验节点（K线连续性）” |
| 量化节点深度 | 指标与因子扩展、标的池筛选 | 仅均线，标的池未入 P0 | 中匹配 | P0 增加“标的池筛选基础版”；复杂因子延后 P1 |
| 流程体验 | 模板复用、单节点调试、中间结果可见 | 已覆盖保存加载、单节点试运行 | 高匹配 | 增加“标准模板中心（首批3个）”为 P0.5 |
| 数据落地 | CSV/Parquet/DuckDB/SQLite + 回测框架适配 | 已覆盖主要格式与 Backtrader/VNPY | 高匹配 | 增加“导出前格式校验器”避免回测导入失败 |
| 调度可靠性 | 定时任务、失败重试、告警 | 现有 P0 未覆盖失败重试/告警 | 中低匹配 | 失败重试（P0），告警通道（P0.5） |
| AI能力 | 脚本生成 + 本地模型 + 流程生成 | 已覆盖脚本生成与 Ollama | 中高匹配 | 增加“量化场景提示模板库”提升生成稳定性 |
| 安全隐私 | 密钥加密、本地运行、数据保护 | 有原则要求，缺可验收机制 | 中匹配 | 明确加密、脱敏、水印、审计验收口径 |

## 4. P0 范围重构（Must/Should/Could）

### 4.1 P0 Must（0-3 个月必须上线）
1. 合规接入与合规弹窗闭环（不可跳过）  
2. 本地文件批量导入与 100 行预览  
3. 基础清洗节点（缺失值、异常值、去重、字段筛选重命名）  
4. 量化核心节点（复权、涨跌停/停牌标记、周期转换、MA）  
5. 导出适配（Backtrader/VNPY + CSV/Parquet/DuckDB/SQLite）  
6. AI 脚本生成（可复制/保存）+ 本地 Ollama 接入  
7. AI 交互式辅助（覆盖凭证、数据源、连接管理、工作流全过程）  
8. 工作流保存/加载 + 单节点试运行  
9. 数据安全底线（密钥加密存储、本地处理不上传）  

### 4.2 P0.5 Should（可并行开发，影响体验与留存）
1. 数据完整性校验节点（K 线连续性、重复时间戳检测）  
2. 标的池筛选基础版（行业/市值/成交额三条件）  
3. 标准流程模板中心（3 套模板）  
4. 任务失败自动重试（指数退避，最多 3 次）  
5. 日志分级筛选（错误/警告/信息）  

### 4.3 P1 Could（延后到 3-6 个月）
1. BOLL/KDJ/CCI/ATR 与因子库扩展  
2. 数据血缘追踪、数据资产目录完整版  
3. 自然语言直接生成可视化流程（非脚本）  
4. 团队协作与权限体系  

## 5. 模块级优化改造清单（可直接给研发）

## 5.1 数据源管理模块（P0）
### 改造项 A：合规使用模式（新增，P0）
- 需求：新增“合规模式”全局开关，默认开启；关闭需二次确认并记录审计日志。
- 规则：导出时识别潜在分发场景（批量导出 + 外部共享路径）并二次提示。
- 验收：
  - 首次连接任一内置数据源必须弹窗并强制确认。
  - 合规模式开启时，存在疑似分发行为则阻断并提示原因。
  - 产生本地审计记录（时间、数据源、操作类型、结果）。

### 改造项 B：连接可靠性参数（新增，P0.5）
- 需求：数据源连接增加超时、重试、并发数配置（默认值可用）。
- 验收：
  - 弱网环境下连接失败可自动重试并给出明确错误分类。
  - 大批量标的拉取不出现无提示中断。

## 5.2 可视化工作流模块（P0）
### 改造项 C：数据完整性校验节点（新增，P0.5）
- 需求：提供“完整性校验”节点，检查交易日缺失、重复时间戳、OHLC 合法性。
- 验收：
  - 输出校验报告（问题类型、条数、样本行）。
  - 支持“一键补全缺失交易日（基于交易日历）”。

### 改造项 D：标的池筛选基础版（新增，P0.5）
- 需求：支持按行业/市值/成交额筛选标的池并保存复用。
- 验收：
  - 多条件组合筛选结果准确。
  - 标的池可保存并被后续流程节点引用。

### 改造项 E：流程模板中心（新增，P0.5）
- 模板清单：
  - 日线行情清洗模板
  - 分钟线转日线模板
  - 均线回测数据生成模板
- 验收：
  - 一键加载后仅需修改 1-2 个参数即可运行。

## 5.3 数据落地与调度模块（P0）
### 改造项 F：导出前格式校验器（新增，P0）
- 需求：导出 Backtrader/VNPY 前自动校验字段名、顺序、类型、空值比例。
- 验收：
  - 校验失败时给出明确修复建议（缺字段、类型冲突、时间格式错误）。
  - 校验通过后导出成功率 >= 99%。

### 改造项 G：任务失败自动重试（新增，P0.5）
- 需求：数据拉取与导出任务支持自动重试（1s/3s/9s）。
- 验收：
  - 瞬时网络故障场景下任务恢复成功。
  - 超过重试上限后保留失败原因与重试轨迹。

## 5.4 AI 辅助模块（P0）
### 改造项 H：量化场景提示模板库（新增，P0）
- 需求：内置 10 条高频提示模板（拉取-复权-指标-导出全链路）。
- 验收：
  - 模板生成脚本可直接运行比例 >= 90%。
  - 用户可一键填参生成，不需从零描述需求。

### 改造项 I：本地模型调用可观测性（新增，P0.5）
- 需求：展示模型名、耗时、token 估算、失败原因。
- 验收：
  - 模型连接失败可定位为端口、模型不存在或超时。

### 改造项 L：AI 交互式上手助手（新增，P0）
- 需求：在用户首次使用与高频操作节点提供“边做边引导”的对话式助手，不跳出当前页面完成配置与排错。
- 覆盖范围：
  - 凭证辅助：引导填写 API Key/账号密码、校验格式、敏感信息遮罩展示、一键测试与错误解释。
  - 数据源辅助：根据用户目标（A股/期货/分钟线/日线）推荐数据源与最小必填参数组合。
  - 连接管理辅助：自动建议超时、重试、并发默认值；连接失败时给出可执行修复步骤。
  - 工作流辅助：根据自然语言意图推荐节点链路（如“拉取->复权->均线->导出”），并逐步确认关键参数。
- 交互机制：
  - 分步向导：每步仅展示当前必要输入项，完成后自动进入下一步。
  - 上下文提示：在字段旁展示“为什么需要此参数/典型示例/常见错误”。
  - 一键修复：对可自动修复问题（字段缺失、时间格式）给出“应用修复”按钮。
  - 失败兜底：连续失败 2 次后自动切换“诊断模式”，收集日志并生成排查清单。
- 验收：
  - 新手用户首次完成“连接数据源->运行工作流->导出”的成功率 >= 85%。
  - 凭证与连接相关问题中，AI 建议可直接解决比例 >= 70%。
  - 关键流程平均交互步数下降 >= 30%，且无新增合规风险。
  - 引导全程不暴露明文密钥，不上传用户原始数据。

## 5.5 安全与隐私（P0）
### 改造项 J：密钥与敏感信息保护（强化，P0）
- 需求：API 密钥、数据库密码本地加密存储；日志默认脱敏显示。
- 验收：
  - 配置文件中不出现明文密钥。
  - 日志中密钥、Token、密码均以掩码展示。

### 改造项 K：导出水印（新增，P0.5）
- 需求：导出文件可选写入来源标识与时间戳水印（元数据层）。
- 验收：
  - 不影响回测框架兼容性。

## 6. P0 里程碑与排期建议（12 周）
- 第 1-2 周：合规模式、密钥加密、基础导入/预览体验收口
- 第 3-5 周：清洗与量化核心节点稳定性、单节点调试增强
- 第 6-8 周：导出校验器、回测框架适配一致性、失败重试
- 第 9-10 周：AI 模板库、Ollama 可观测性、日志分级
- 第 11-12 周：联调压测、灰度发布、问题闭环

## 7. P0 验收标准（统一口径）
- 功能正确性：核心链路用例通过率 100%，无阻断级缺陷。
- 数据准确性：复权、周期转换、MA 与基准工具比对误差在可接受范围内（业务定义阈值）。
- 可用性：新手 5 分钟内完成“接入->处理->导出”全流程。
- 交互效率：AI 引导后，关键任务平均完成时长下降 >= 30%，关键步骤中断率显著下降。
- 性能：10 支标的 x 1 年分钟线处理，无崩溃、无卡死。
- 安全：密钥不落明文，数据默认本地处理，合规提示不可绕过。

## 8. 实施注意事项（避坑清单）
- 不在 P0 同时引入过多高级因子，避免牺牲稳定性。
- 先做“导出前校验器”再扩展更多导出格式，避免兼容性债务。
- 失败重试必须可观测，避免“静默失败”造成用户误判。
- 合规功能要“可执行”而非“仅提示”，否则难以规避风险。
